# 局部路径合并与后处理评估状态

2026-11-03：完成 Sv39 全符号页表 A/B 对照实验（基线分叉 vs 局部线性化 vs 线性化+笛卡尔积后处理）。产物见 `.worktree/mmu-symbolic-experiment/exp-ab-comparison/`，机器记录见 `comparison_report.json`。

实测结论：
1. **局部线性化收益**：压平 `zpte_is_non_leaf` 与 `zpte_is_invalid` 后，Z3 求解次数从 89,017 次下降 59.2% 至 36,314 次，探索路径总数从 179 下降 41.3% 至 105；打破了基线的“浅层偏斜”，首次打通全部 3 级页表（1GiB、2MiB、4KiB）。
2. **笛卡尔积后处理效能**：在提取出的 3 级结构模板上，后端对 3 权限 × 2 特权 × 2 状态展开 36 个微架构用例，Z3 批量求解**总耗时仅 70.36 毫秒（平均 0.452 毫秒/例）**，36/36 经 Sv39 规则核对 100% 合法，无脏用例。
3. **未解决的瓶颈与局限**：
   - 线性化两函数后仍有 105 条路径并在 60 秒触限（`check_PTE_permission` 和 `update_PTE_Bits` 仍有 25 处分支）；
   - 首条命中时间从 9.14s 升至 16.96s（AST 深度微增带来单次开销，线性化省的是组合爆炸而非单条延迟）；
   - 笛卡尔积只能扩增已知路径的数据流，无法替代探索新的控制流异常分支。

历史架构调查保留：
当前快照复制容器，Arc 不构成完整 COW；solver 恢复新建并重放。历史分支 6cbefb494da1c3e5c6245667a12cb67adbba878a 的 merge_traces 仅加事件，start_single 合并保留主 solver，失败丢弃已取出的兄弟任务；OpenMerge/CloseMerge 仅推进 PC。不能直接用其路径减少证明性能。


vmem_pte.sail 局部检查无直接内存写；update_PTE_Bits 返回修改后的值，实际写回在 vmem.sail。整段页表遍历不满足无副作用假设。

既有单线程60秒至少415条、8564次检查累计26.629秒；16线程至少3181条，均非完整总数。尚不能分离复制、重放、查询、具体化和日志成本。

实验建议：固定同源版本/IR/官方Z3，比较直接fork、fork+COW、局部合并、局部合并+COW；后三者实现后另验。先纯BV菱形语义回归，再单PTE检查，最后原Sv39。合并组计入条件组合筛选与见证成本；与直接组比较相同可达分支组合及输出状态，不只比较终态数。

正确性门：共同前缀上重建带guard的两臂定义/断言，隔离符号命名；明确汇合点及调用栈；保留失败任务；禁止无支持的内存/回调副作用；保存动态条件的活动guard及来源。笛卡尔积必须满足原程序可达性，不能把短路未执行条件作为自由覆盖维度。
