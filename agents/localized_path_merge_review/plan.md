## 2026-11-05 后处理展开设计（用户倾向：两个来源都纳入计划，尚未开始实现）

**整体目标**：符号求解得到页表结构，交给后续测试模板建页表，不预设页表形状。细碎位域（V/R/W/X/U/G/A/D/RSW 等）在执行期不分叉，求解后在后处理中展开。

**执行期**：合并只发生在单入口单出口区域内部（如 `pte_is_invalid` 的短路检查链合成一个布尔值）。“非法还是继续”“在哪一级结束”等宏观分叉仍然保留，异常路径照常产出。位域在路径约束里必须保持自由，不得被预算或具体化锁死，否则后处理对它们提假设只会得到 UNSAT。

**后处理（本次要实现的两个展开来源，可同时使用）**：
1. TOML 声明：按函数的原始名字（Sail 里怎么写就怎么写，isla 内部转码）指定要展开的参数或返回值，可限定到某些位。
2. 自动来源：被动态路径合并折叠的区域，其输入变量自动成为展开对象。

**展开算法**：路径结束后，在该路径自己的 solver 里做投影模型枚举：对展开对象反复 check-sat、取模型、加阻塞条件，直到 UNSAT 或达到上限。每个解都满足真实路径约束，因此不需要另外的合法性核对。上限触发时必须在输出中标明被截断，不得静默截断。成功路径和异常路径都要展开；合并后“哪一项检查触发了非法”不再是单独路径，要靠异常路径上的展开恢复。

**通用性约束**：isla-lib 不得出现 `check_PTE_permission` 之类的 Sail 函数名，具体名字只在 TOML 中出现。

**先不做**：PPN 与地址空间配置的联动、采样、模板侧建页表。

**未决**：展开结果在 JSON `gen[]` 中的字段格式；多个展开对象之间是否分组；上限默认值。

**验证要求**：先写测试。纯位向量小例子上，展开结果必须与暴力枚举（逐个组合带路径约束检查）一致；再用真实 `pte_is_invalid` 做回归。此前实验脚本中 Group D 的校验（手写公式、写死模板）不算验证，见 `.worktree/mmu-symbolic-experiment/run_comparative_experiment_with_pathmerge.py` 第 252～330 行。
