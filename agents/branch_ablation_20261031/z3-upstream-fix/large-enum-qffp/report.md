# 当前default与直接qffp的大枚举比较（2026-11-01）

“大”按新probe的枚举模型转换成本判断：对每个唯一符号枚举常量，累计该类型的构造器个数。超过4096沿原default路径。不是以枚举数值的位宽或单个枚举变量的值大小判断；例如512构造器×256变量＝131072。

使用当前带成本护栏的同一个Z3二进制，SHA256为99d27e45f13f1d805a3c416327e428d72dc3c151d742c8324f642e869af161c6。简单的fp.isNaN(x)与独立枚举排除C0约束用于暴露转换开销，不是完整Clause或复杂浮点运算。每组同一输入、同CPU100，每策略5次AB/BA交替，Tactic仅default/qffp不同。计独立进程墙钟（含进程启动），所有70运行均SAT。相比作者前次初版性能数据，本轮只比较当前带护栏default与直接qffp，不混算未修default或初版补丁。

结论：超过护栏的大枚举例中，两策略绝对差约2–3ms，仍有范围重叠，不解释成稳定普遍比值。护栏内的轻量FP例，default仍可能比直接qffp慢约20ms，因为会转枚举而qffp直接保留其给后端；这再次说明不是每个query都会更快。
