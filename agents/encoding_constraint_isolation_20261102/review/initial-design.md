# 编码约束隔离：独立设计审查

状态：准备审查；尚未签收源码或结果。审查对象是先去除原执行 `Assert` 探索全部编码分支，再将每个分支增量合并回完整原执行 checkpoint 的方案。

已核对根规则、`specs/GOAL.md`、`specs/ir-workflow.md`、`GIT.md`、`GPT_SAY.md`、当前 `isla/src/isarch/encoding.rs`、collector、SMT checkpoint/replay 与超时确认报告。当前源码基线仍由原执行 checkpoint 直接进入普通编码，对普通拒绝域接续压缩编码。

## 必须保持的条件

1. 去除 `Assert` 只扩大候选探索域；原 `DeclareConst`、`DeclareFun`、`DefineConst`、`DefineEnum` 及符号号分配必须保留。定义可以携带原路径上的数值关系，不能把它们当作无关内容删除。
2. 最终验证等价于原完整执行约束与候选编码分支约束的合取。恢复完整原 checkpoint 事件，随后只接候选新增事件；不得重复整个候选前缀，不得遗漏非 SMT 事件。`num`、`next_var`、祖先段和事件顺序须自洽。
3. 普通成功域优先，只有普通正常拒绝域才接续压缩。普通拒绝条件在接续压缩时不能被再次隔离掉。每个可达成功终态单独保留，不提前具体化成一个模型，也不只取首候选。
4. 隔离后新增的不可达异常分支也要按完整原约束判断可达性。完整合取 UNSAT 可过滤；SAT 应保留原异常分类；UNKNOWN/SMT error 不能当作无编码或普通拒绝。超时和采样不得伪装成成功。
5. 最终返回的每份 checkpoint 需同时约束初始配置、原执行路径和编码分支，随后现有 collector 才能用一个最终求解模型具体化参数、前态、后态、返回值及编码。

## 建议回归

- 原约束排除某个辅助分支时，候选探索确实访问该分支，但最终结果不含它。
- 两个同时可达编码分支仍全部返回；普通拒绝接续压缩，普通成功域不返回重叠压缩结果。
- 原约束排除的辅助 AssertionFailure 不阻断有效编码；原约束下可达的 AssertionFailure 仍使求解失败。
- 原枚举定义、声明函数、嵌套定义以及新增枚举/符号经隔离、合并、replay 后仍有正确含义，下一 fresh 不碰撞。
- 完整 checkpoint trace 保留原断言和事件，候选前缀不重复；错误的祖先合并应明确拒绝。
- 真实 Clause 完整退出状态、JSON 编码与初/后态分别核验，性能数据只对固定版本和配置有效。

该方案在满足以上条件时有可证明的等价路径：每条原可达辅助分支仍在扩大的候选域内；最终完整合取剔除新增不可达分支。尚未看到最终实现，不能据此写源码或动态 PASS。
