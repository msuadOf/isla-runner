# 保留指令字段断言：后续方案独立审查

结论：可行，建议作为当前两处 Rust 改动的局部修订；最终完整验证、normal 优先、compressed 拒绝域和错误传播不变。尚未实施或验证性能，本文件不签收新源码或新性能结果。

## 等价依据

令完整原路径为 `C = 定义D ∧ 原断言A`，辅助保留原断言的子集 `R ⊆ A`，则 `C ⇒ D ∧ R`。所以辅助域仍包含每个原来可达的输入；完整原约束与每个候选增量的最终合取不变。保持全部候选与原异常分类，即不会因为保留这些断言而漏原可达编码。

这里不要求断言之间独立。“仅依赖指令字段”的判定决定删去多少昂贵查询，不是最终正确性的额外假设。即使把某条状态相关的原断言保留回来，数学语义仍安全，但可能把原性能问题带回来。相反，少保留一条指令断言只会扩大候选域，最终完整验证仍过滤它。

normal 正常拒绝的新增条件继续作为 compressed 的辅助起点；不能为 compressed 重新筛掉这些条件。原 `with_suffix_from` 合并方式继续适用：保留断言属于辅助基点，完整原 checkpoint 已含它们，不能把整个辅助前缀重复接回。

## 建议的最小规则

复用 `instruction.symbolic_variables()`，不要新增不完整的值遍历。现有 API 已覆盖结构体、向量、列表、构造子、`MixedBits` 与 `SymbolicCtor` 的 tag/各载荷。

按事件原序维护每个符号是否只由指令输入及常量构成：

1. `DeclareConst(v, ty)`：仅当 `v` 出现在上述输入符号集合时标为纯。其余初态、内存、浮点数据等声明不标纯。
2. `DefineConst(v, exp)`：仅当表达式引用的所有符号此前已标纯时标纯；纯常量表达式可标纯。务必沿定义传播，不能只看最终 Assert 直接出现的临时 Bool。
3. `Assert(exp)`：仅保留整个表达式为纯的原事件；其余暂时移去。保留的表达式、位置和属性不改写。所有非 Assert 事件及 `next_var` 原样保留。

原 `symbolic_args_from_types → symbolic` 的 op、rm、寄存器编号等字段由 `DeclareConst` 创建，因此该规则能够传播到执行过程中针对这些字段的判断。用布尔纯标记即可，不必给每个定义分配完整依赖集合或做 SMT 查询。只读分类不能根据一个求解模型具体化字段。

## 必须注意

- `Exp::variables()` 的 `App(function, args)` 只遍历参数，不包含函数符号。直接仅检查它的返回集合，会把依赖未知函数解释的表达式叫成“纯”。简单做法是：含 `App` 的表达式归为不保留；不必在本轮建立新的函数依赖系统。这个保守选择不影响最终等价性。
- 若 instruction 的符号自身是一个 `DefineConst`，不能仅因它出现在输入里就无条件标纯；仍分析定义。否则该叶可能是浮点状态计算的别名，把成本重新带回辅助域。当前指令字段主要是独立声明；对派生输入保守少保留仍安全。
- 不把 `Assert(x == op)` 当作 `DefineConst` 传播别名。Assert 是关系约束，`x` 仍可能连接状态数据。单向定义分析可能无法发现跨多个 Assert 才成立的纯字段限制；这是性能上的漏保留，不是最终约束遗漏。
- `Assert(And(pure, state_related))` 可以先整体移去，不为局部收益拆解/重写原断言。当前独立 op/rm 分支通常各有 Assert，可先测简单规则是否已消除无效候选。
- Ground FP 表达式的依赖集合可为空；“只依赖指令”不自动等于便宜。可记录保留断言是否含 FP/数组/未知函数的传递依赖。若遇真实此类成本，再考虑仅保留 Bool/BV/Enum 的更窄规则，不能只看断言结果是 Bool。
- 依赖规则无法证明某式纯时，将该原 Assert 暂不保留，是定义明确的候选域放宽；不能据此吞掉执行器或最终检查的 UNKNOWN/error。最终 UNSAT 才可过滤候选异常。采样检查仍先于过滤，Dead 的子集证明保持。

## 更简单的备选

若要少传一个 instruction 参数，另一种同样等价的子集选择是：只移去传递依赖包含原生 FP 操作的原 Assert，保留其余原断言。它可一遍传播“含 FP”标记，并保留初态配置及所有普通字段 guard。但它会保留状态相关 BV/数组约束，不能保证它们便宜；未知函数和已展开成 BV 的运算也须单独核对。当前已明确看见 op/rm 引发无效候选，优先采用上述指令字段规则更符合本次限定目的，不需要同时实现两套模式。

## 验证与性能边界

至少先补以下红绿例：两级定义后的指令 guard 被保留；经同样定义链混入状态的 guard 被移去；嵌套/MixedBits/枚举 tag 字段完整；未知 App 不误判；原指令 guard 剪去不可能候选，两个真正可达编码仍全部保留；可达/不可达辅助异常与压缩拒绝域保持。原完整配置、前后态及编码同模型回归也要复验。

实际观测须分别记录保留/移去断言数、辅助终态数、最终完整 SAT/UNSAT 次数及耗时。当前6个主路径内148次已返回完整检查含124 UNSAT，足以支持减少无效候选的方向，但不证明这个规则一定让完整旧 flags 在7200秒完成。仍在运行的两项正式全域输入不受本设计审查影响；后续版本改变后旧 PASS 只作原版本证据。
