## 2026-09-26 接续调整：复用已有 Sail 类型

用户在本轮实施中明确要求 IEEE 层更多复用 Sail-RISC-V 已有类型体系。两名 Astra xhigh 对当前源码与已安装 Sail 库复核后，按此要求调整原共享接口：

2. 复用 prelude 已导入的 `fp_exception_flags` 作为最终共享编码，位序为 NV0/DZ1/OF2/UF3/NX4；只在 RISC-V 包装处转为 `bits_fflags` 的 NV4/DZ3/OF2/UF1/NX0。首候选曾将所有内部事实替换为位串，未知输入门槛出现明确性能回退；按[单因素对照](type-reuse-performance.md)的结果，最终采用 C1：保留局部 `ieee_fp_exceptions` 五Bool事实结构和 `ieee_exception_facts` 构造，在出口只调用一次 `ieee_pack_shared_flags`。这样复用已有格式及编码体系，同时避免每层Bool/BV打包读取。异常公式、数据域及 ISA 分层职责不变。
3. 复用 `float_bits`/`float_decompose`，把按格式手切片的分类辅助合并成泛型严格布尔适配。已有 `float_is_*` 包含数据相关短路分支，不能直接引入67个纯 helper；新适配须用实际 IR 和未知输入验证不增加执行分叉。`float_decompose` 的 IR 可保留按已知 BV 位宽选择的分支；门槛是固定格式的未知数据调用仍恰好一条完成路径、没有新增数据相关 fork，不能把静态出现 Jump 本身当作失败。BF16不能当作IEEE binary16分类。
4. 保留现有通用原语绑定出口，不为消除别名而重命名全ISA类型，也不替换 Z3 数值运算与已审异常/ROD算法。

## 1. 要完成什么

让 RISC-V 标量和向量浮点指令得到正确的计算结果和异常标志，同时按下面的标准划分代码职责。

### 主要判断依据

用户明确的依据是：**IEEE 标准的浮点数值计算由 Z3 支持，通过 Isla 的 primop 提供；ISA 需要的 flags、分支和状态行为由模型负责。**

例如，浮点加法使用 Isla 的通用浮点加法接口，内部调用 Z3 的 `fp.add`。不在 Isla 或 Sail 中用一套 ITE 重新实现已有的 IEEE 加法、除法或开方。

Isla 同时提供通用 ITE，供模型把“按条件选一个值”写成表达式；哪种情况选哪个架构规定的值，由模型决定。这里的“数值计算不靠 ITE 重写”不禁止模型使用 ITE 选择输入、舍入方式或返回值。

### 交叉检查：换成 ARM 或 x86，还能原样使用吗

审查每个拟新增或保留的浮点 primop 时，假设调用方分别是 RISC-V、ARM 和 x86，依次检查：

1. **能否不提 ISA 名称，就说明它怎么算？**格式、舍入方式和输入值要明确，不能暗含某个架构的寄存器或指令规则。
2. **换一个 ISA，相同参数是否仍表示相同操作？**同名指令不一定相同，要核对 NaN、舍入和越界等规则。ISA 特有的输入处理和结果处理放在各自模型中。
3. **现有 Z3/Isla 操作能否直接表达？**能直接表达就复用。缺少必要的通用操作时才补 primop；通用纯组合可以内部使用已有运算和 ITE，但要写清为什么不能直接复用已有接口。

| 内容 | 放在哪里 | 换 ISA 后看什么 |
| --- | --- | --- |
| `fp.add(rm, a, b)`、乘除、开方及标准转换 | Isla primop，调用 Z3 原生操作 | 操作含义不随 ISA 改变；ISA 把格式、舍入方式和输入传入 |
| `ite(condition, x, y)` | Isla 通用 primop | 所有模型都使用相同的“条件为真选 x，否则选 y” |
| RISC-V 的 rm 位编码转换为通用舍入方式 | RISC-V 模型，组合通用 ITE | ARM/x86 的控制位不能按 RISC-V 编码解释 |
| NaN 时返回哪个位串、无效整数转换返回什么 | 各 ISA 模型，组合通用运算和 ITE | 规则由具体 ISA 决定，不能藏在通用浮点操作里 |
| 本次运算是否发生无效、除零、溢出、下溢、不精确 | Sail 共享浮点模型函数 | 相同的 IEEE 异常规则可以共用；检测方式等差异需要明确 |
| flags 位次、累计、屏蔽、trap、寄存器和跳转行为 | 各 ISA 模型 | 读取和修改的是具体 ISA 状态 |

**能被多个 ISA 使用，是检查通用性的办法，不表示所有共用代码都必须放进 Isla。**本计划仍将 IEEE 异常判断放在可复用的 Sail 模型函数中。也不能把整个 RISC-V 函数改成通用名字、内部改用 ITE，就视为通用 primop。

**是否用了 ITE，不决定代码归属。**通用条件和值可以组成通用操作；带 ISA 含义的条件和值由 ISA 模型提供。ITE 本身始终只是选值。例如 `ite(is_nan(r), RISCV_NAN, raw_bits)` 可以直接写在 RISC-V 模型里，调用现有 ITE 就能形成一个表达式，不需要新增“RISC-V NaN 处理 primop”。

这里用三个 ISA 检查设计是否通用；本计划的实现和测试范围仍是 RISC-V，不要求新增 ARM/x86 模型。

### 按此标准分工

| 放在哪里 | 负责什么 | 不在这里处理什么 |
| --- | --- | --- |
| Isla 通用浮点接口 | 将加减乘除、乘加、开方、比较和转换等操作交给 Z3；提供浮点值与位串的转换、舍入方式及通用条件选择 ITE | RISC-V 指令名、rm/frm 编码、规定的 NaN 返回位、fflags/CSR 更新 |
| Sail 共享浮点模型函数 | 根据操作和原始输入位，计算本次操作的五个异常标志；数值计算仍调用 Isla/Z3 的通用浮点操作 | RISC-V 寄存器编号、标志位编号和状态更新 |
| Sail RISC-V 模型 | 解释 RISC-V 舍入方式；选择规定的 NaN 和无效整数转换结果；打包并累计 flags；更新寄存器，处理合法性、跳转和向量控制 | 在 Isla 执行器里按指令或函数名补 RISC-V 语义 |

五个异常标志分别是：无效操作（NV）、除零（DZ）、溢出（OF）、下溢（UF）、不精确（NX）。共享模型返回五个独立的布尔值，RISC-V 模型再按自己的位次打包。

Z3 不直接返回这五个标志，也不保留原始 NaN 的全部位信息。因此模型保留原始输入位，用于区分两类 NaN 和检查其编码；数值运算使用 Z3 浮点值。

### 几个名称具体指什么

| 名称 | 本文中的意思 |
| --- | --- |
| 原始位串、bits、BV | 寄存器里的 16/32/64 位编码。例如 f32 的 `0x3f800000` 表示 1.0；对它做按位异或与做浮点加法是两件事 |
| FP 值 | Z3 内部用于计算的浮点值。由原始位串转换而来，但不能保存原来 NaN 的全部编码细节 |
| RM | 舍入方式，例如向零或向正无穷。Z3 接收专门的舍入类型；RISC-V 的三位 rm 编码须由模型先解释 |
| primop | Sail 模型能够调用、由 Isla 直接执行的基础操作，如浮点加法或选值 |
| helper | 被多条指令调用的辅助函数。本文的 79 个 `riscv_*` helper 返回一次运算的结果和标志；它们不等于 73 个通用 primop |
| ITE | `ite(条件, 真时的值, 假时的值)`，得到一个值。条件未知时把选择保留在求解公式里 |
| 执行分叉 | Isla 因未知条件分别执行两条程序路径。使用一个 ITE 表达式本身不会创建这两条执行路径，但仍会增加求解器需要处理的内容 |

### 用具体操作说明边界

**例 1：f32 加法与 NaN。**模型先保留输入位，再把输入转换成 FP 值，调用一次 `fp.add`。输入是 qNaN 和 1 时，Z3 给出 NaN 数值；RISC-V 包装将返回位选为 `0x7fc00000`。共享异常函数检查原始输入，qNaN 不因此置 NV，sNaN 则置 NV。最后指令把本次 flags 与旧 `fflags` 按位 OR。这里有四件事：算数值、判断异常、选规定的返回位、更新 CSR，不能全塞进一个 RISC-V 专用 Isla 算子。

**例 2：浮点转 i32 要看舍入后的值。**f64 `2147483647.75` 在就近取偶数时成为 `2147483648`，超过 i32 上界，RISC-V 返回 `0x7fffffff` 并置 NV，不同时置 NX。`-2147483648.25` 则舍入到合法的 `-2147483648`，返回 `0x80000000`，只置 NX。计划先用原生 `roundToIntegral` 舍入，再检查范围；不能只比较原始输入是否超过整数最大值。无效输入下原生 FP→整数结果未指定，模型必须用 ITE 选规定返回值。具体算法仍需实施和验证，见设计说明。

**例 3：ROD 与普通 rm=6 分开。**`vfncvt.rod.f.f.w` 内部会向转换 helper 明确传 6。f32 的 `1 + 2^-12`（`0x3f800800`）转 f16，先向零舍入得到 `0x3c00`；因为不精确，ROD 把最低有效位置 1，得到 `0x3c01`，置 NX。精确的 1.0 则仍为 `0x3c00`、flags 为 0，不能无条件 OR 1。这是派生窄化算法，不是 Z3 的第六个原生舍入值。普通指令从 `frm` 读到保留编码 6，仍按 ISA 合法性规则处理，不能借此允许普通加法使用 ROD。特殊值、溢出和下溢还须另测。

**例 4：被屏蔽元素不能修改 flags。**`VFWMACCBF16_VF` 的标量源若是合法装箱的 BF16 sNaN（低 16 位 `0x7f81`），而 `vl=0` 或全部元素被屏蔽，本次指令不应因该标量置 NV。当前模型在检查活动元素之前调用了会累计 flags 的转换函数，因此需要移动累计动作。可以提前纯计算转换值和本次异常，但只有实际执行元素时才能修改 CSR。

**例 5：ITE 的未选中参数也会先计算。**`ite(active, accrue_fflags(...), ...)` 不能保证 `active=false` 时不更新 CSR。应先用纯函数得到值和 flags，再在正确的指令控制流里累计。另一个已有接口 `isla_mux2(selector, false_value, true_value)` 只选位串，真/假参数顺序与 `ite` 相反，不能照抄调用。

## 3. 验收标准：逐条检查什么

### 1）Isla 的通用操作能由不同 ISA 模型复用

- 检查 Isla 的浮点接口只提供通用计算和转换。
- 按第 1 节逐个检查浮点 primop：写清操作含义、对应的 Z3/已有 Isla 操作，以及换成 ARM/x86 后是否需要改变它。必要的通用组合注明 ITE 的用途；不能包含某个 ISA 的 flags、返回值或状态规则。
- 检查异常判断、RISC-V 规定的返回值及状态更新放在 Sail 模型中。
- 删除旧浮点专用分发后，重新运行全部相关模型函数，确认它们确实通过模型执行。
- **通过条件：浮点 primop 的操作含义与 ISA 无关；RISC-V 模型不依赖旧分发，没有缺失函数错误，结果和标志位测试仍然通过。只查代码里有没有某个名字不算完成。**ARM/x86 用作设计检查，不要求本次实际运行它们的模型。

### 2）计算结果和五个标志位都符合对应规则

每项先写清预期结果从哪里来，不能把所有操作都拿一个普通 SoftFloat 运算来比较。

| 被测内容 | 用什么判定正确 | 必须比较什么 |
| --- | --- | --- |
| 67 个原外部 helper 的算术、比较、开方、取整和转换 | 固定版本的 SoftFloat 及现有 C++ 包装，固定 RISC-V 专用配置、舍入后检测下溢的设置，以及 ROD/BF16 编译选项 | 相同输入下的完整结果位和全部五个 flags；不是只检查其中一个 flag |
| 原有 6 个窄整数转换包装 | RISC-V 的目标整数范围、无效返回值、NV 对 NX 的优先规则；底层 32 位转换另与 SoftFloat 比 | 窄化后的结果与 flags，例如越界时不能继续保留普通不精确转换的 NX |

- 包含正负零、正负无穷、qNaN/sNaN、最大有限数、最小正规数、次正规数，以及相邻边界值。
- 浮点转整数包含刚好能表示、刚好超出范围、舍入后才进入或超出范围的值。

### 4）纯计算中的条件选择不增加执行路径

- 检查舍入方式选择、NaN 返回值选择、无效整数转换结果选择和 flags 计算。
- **通过条件：上述纯计算选择产生的执行分叉为 0，并有生成的 IR 和执行记录支持。**
- 完整指令中的非法编码、跳转、寄存器更新等判断另行测试，不能要求所有指令只有一条执行路径。
- 原有 12 个 Sail 函数体需要正确性回归；本次不把 Recip7/Rsqrte7 的全部查表及归一化循环改成无分叉表达式。若后续为了性能改造其中某个纯选择，单列该改动的范围和证据，不能把 67 个迁移函数的要求泛称为“所有浮点指令零分叉”。

- 原有 12 个已有函数体的函数保留，并运行相应测试。
- 新生成的 IR 要实际运行标量和向量浮点指令，检查结果写回、动态舍入方式、NaN boxing、flags 累计、mask 和 vstart。被屏蔽或未执行的向量元素不能贡献异常标志。
- 专门覆盖 `VFWMACCBF16_VF` 的标量 sNaN：`vl=0`、全 mask=0、`vstart>=vl` 时原 flags 应保留；再测有活动元素时按规则累计 NV。旧 flags 分别取 0 和非零值，确认是 OR 累计。另一个用例将 sNaN 只放在被 `vstart` 跳过的向量前缀，标量和实际执行元素用普通有限数，验证跳过的元素不贡献 NV。当前累计位置问题见 [参考表 M07](reference-list.md)。
- 当前 FD_FLOAT 的 89 个条目是执行函数的分支名称（clause），不是 89 条指令编码，也不是 89 个 helper。逐项登记后，还要记录每项的格式、子操作、舍入方式、扩展开关、XLEN、合法编码和实际生成的指令。`VFNUNARY0` 名称被跑到不代表其中 ROD 子操作被跑到；配置没启用 Zfa/BF16 也不能写相应指令通过。`LOAD_FP`、`STORE_FP` 各含 H/W/D 三种宽度，其中 H 的 FLH/FSH 需要 Zfhmin 或 Zfbfmin；8 个压缩浮点访存条目也依赖实际内存执行。仅返回一个已完成路径不能证明发生了读写。`C_FLW`/`C_FSW` 四项与 `FMVH_X_D`/`FMVP_D_X` 的合法编码受 RV32 限定，固定 RV64 配置不能证明它们合法执行；须另用 RV32 配置验证，或仅将 RV64 非法路径记为非法路径覆盖。直接注入 clause 构造器也不等于验证合法译码。
- 普通 `make solve` 排除了 FD_FLOAT，不能用它通过来代替浮点测试。89 项中未执行、无法生成或被配置排除的情况明确单列。
- **通过条件：覆盖清单中的必测项全部通过。缺实现、错误、不确定、超时和未测都单列，不能计为通过，也不能据此说全部完成。**

测试前固定清单、配置、超时、线程数和内存限制，不能在结果出来后删掉失败项。一个阶段通过只说明该阶段列出的内容通过，不代表完整浮点支持已经完成。
