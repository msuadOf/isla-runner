# 浮点接口与模型修改参考总表

日期：2026-09-26。判断依据见 [实施计划第 1 节](plan.md#1-要完成什么)：**IEEE 数值计算使用 Z3/Isla 通用操作，ISA 的异常标志、分支和状态由模型负责；再检查换成 ARM、x86 后，通用操作的含义是否保持不变。**

这是一份检查结果和修改参考，不是已完成的实现。未改源码或 IR，未运行 Isla 全量浮点测试。“保留”表示本次检查未发现需要改变的操作含义，不代表所有输入已经验证。

## 2. Isla 侧：需要修改或补充的项目

| 编号 | 对象 | 检查结论 | 修改参考 |
| --- | --- | --- | --- |
| I01 | `fp16/32/64/128_from_ieee` | **必须改入口**。只接受 Symbolic，具体和混合位串不能调用 | 复用已有值转换，检查输入位宽；三个输入形式在同值时结果一致 |
| I02 | `fp16/32/64/128_from_signed`、`..._from_unsigned` | **必须改入口**。整数源同样只接受 Symbolic | 接受具体/混合 BV；保留已合入的目标格式修复，不重新写一套数值转换 |
| I03 | FP→IEEE 位串 | **必须补公开 primop**。SMT 和 Z3 接线已有 | 新接口只负责位编码；NaN 编码限制写清，不做 ISA canonical NaN 选择 |
| I04 | FP→无符号整数 | **必须补公开 primop**。ToUnsigned 底层已有 | 至少覆盖模型需要的 32/64 位；按现有 signed 家族确定其他宽度，模型处理无效结果 |
| I05 | 现有浮点参数检查 | **必须补检查**。只判断“是 Symbolic”不能确保它是 FP 或 RM | 检查 RM 类型、FP 同格式、位串宽度；复用现有类型工具，不重写 SMT 类型系统 |
| I06 | f32→BF16 数值接口 | **必须补可调用路径**。SMT 能表示 `(8,8)`，公开类型不能直接表达 | 先验证纯数值转换到 BF16 bits 的通用接口；必要时再扩展类型，不把 f16 当 BF16 |
| I07 | `softfloat_tests::solve_call` | **必须改测试初始化**。缺少当前要求的 `configure_tastic` | 独立运行这组测试应不依赖其他测试先初始化；补通用原语自己的测试 |
| I08 | Rust 中的 RISC-V 浮点名称分发 | **模型替代后移除** | 模型结果及 flags 验证通过后删除，再确认全部函数仍可运行 |

具体代码位置、参数、注册名和测试要求见 [通用 primop 表](inventory-primops.md)与[支撑层表](inventory-support.md)。

### 可以保留的数值操作

- 五种原生舍入方式；f16/f32/f64/f128 类型、常量和未知值。
- `fp_add/sub/mul/div/fma/sqrt`、`fp_round_to_integral`。
- `fp_abs/neg/rem`、分类谓词、比较、四种目标格式的 `convert`。
- 已有 `fp_to_signed16/32/64/128`：Isla 出口已存在，Sail 声明还需补。
- `fp_min/max` 保持 SMT 含义；RISC-V 的正负零、NaN 和异常规则由模型补充。

这些操作的原生 Z3 映射本次未发现应改成另一种计算的理由；入口、类型和测试问题仍按上表处理。尤其不能把普通 SMT 相等代替 `fp_eq`：正负零、NaN 的比较含义不同。

## 3. ITE：哪些复用，哪些要改

| 对象 | 处理意见 | 注意事项 |
| --- | --- | --- |
| 公开 `ite(condition, true_value, false_value)` | **复用**，用于 Bool/BV/FP/RM 的同类型选择 | 两个候选值提前求值；不能放 trap 或状态修改。补标量及需要的记录测试 |
| `isla_mux2(selector, false_value, true_value)` | **已有 BV 选择可以复用**，不用改成 FP 通用选择 | 参数顺序与 `ite` 不同，仅处理位串，不要混用 |
| `isla_bool_to_bit`、严格 Bool 运算 | **复用**，供纯 flags 表达式和位次打包使用 | flags 条件及位次仍由模型决定 |
| `build_ite` 对 union/Option 等带构造器类型的选择 | **按需修通用缺陷**：若方案使用符号条件选择 union/Option，先修再用 | tag 未与条件关联；交换两臂时未反转条件；同构造器的复杂内容未递归处理。当前浮点标量方案不依赖这条路径，不能把它说成 FP/RM 选择必然错误 |
| `float.rs` 私有 `ite` | 随对应模型逻辑迁移，**不新增一组同义原语** | 通用 ITE 已存在；需要改的是条件、候选值的归属和部分异常算法 |

现有 15 处浮点 ITE 按用途全部覆盖：rm 解码 1 处、flags 打包 1 处、指数辅助 2 处、整数幅值 1 处、NaN 返回值 5 处、无效整数转换返回值 5 处。数量是源码调用点，不是执行路径数。

## 4. Sail-RISC-V 侧：需要补充或修改的项目

| 编号 | 对象 | 需要做什么 |
| --- | --- | --- |
| M01 | 模型调用通用原语的声明 | 增加不与 `rounding_mode` 枚举冲突的声明文件；包括 FP→bits、FP→signed/unsigned、通用 RM 和 ITE。已安装 Sail 原生浮点库仅绑定 73 个现有名字中的 69 个，不能直接认为接口已齐 |
| M02 | 67 个原外部浮点函数 | 保持已有参数和返回形式，增加 Sail 模型函数体；数值调用通用原语，异常由共享模型计算，ISA 返回值和 flags 编码在 RISC-V 包装完成 |
| M03 | rm 解码 | 修正符号 rm 恒为 RNE；普通指令的合法性与动态 frm 仍在模型处理，不能靠 solver 断言过滤非法指令 |
| M04 | **ROD 窄化：`vfncvt.rod.f.f.w`** | 当前真实调用会传 **rm=6**，旧 Rust 对具体值 panic、对符号值排除。补 ROD 模型计算：先 RTZ 窄化，若不精确则将结果最低有效位置 1，并正确处理特殊值和异常。它不是 Z3 第六种原生 RM，也不是“中点取奇数” |
| M05 | 比较、加减乘除、FMA、开方和转换的异常判断 | 修正 [旧报告](report.md)与[本轮专用实现清单](inventory-runtime.md)中的全部错误；NX/OF/UF 不得继续使用已知近似公式 |
| M06 | NaN、无效整数转换返回值、flags 编码 | 从 Rust 专用实现移入模型；原始 bits 负责 sNaN/payload/符号检查，FP 值负责数值计算 |
| M07 | **`VFWMACCBF16_VF` 的标志位累计位置** | `zvfbfwma_insts.sail:102` 在 mask 检查前执行带 flags 副作用的标量 BF16 转换。vl=0 或所有元素不活动、标量为 sNaN 时会提前置 NV；改为只在确有活动元素执行时累计该异常。源码推导，待定向运行验证 |
| M08 | 已有 12 个函数体及外围浮点函数 | 保留现有模型职责并验证。Recip7/Rsqrte7、窄整数转换、分类、符号注入、min/max、NaN boxing、寄存器访问和向量控制不因本次分层一律改成 primop；外围函数如 M07 有独立必修项 |
| M09 | 旧 `feq_quiet_S/D`、`flt_S/D` | 这些函数当前没有调用，但自身对同编码 NaN 相等、`-0 < +0` 的处理有错。后续不能直接复用；应修正或明确弃用。不能把这个潜在问题写成现行 FEQ/FLT 指令已经因此出错 |

### 对照测试按操作选参考

- 对 SoftFloat 确有同语义 API 的算术、比较、开方、取整及格式/整数转换 helper，固定格式、舍入方式、RISC-V specialization、tininess 配置和输入后，逐位比较结果与五个 flags。ROD 窄化只与启用 ROD 的对应 SoftFloat 转换比。
- Recip7/Rsqrte7 是 RISC-V 规定的查表估算，FCVTMOD 是模 2^32 结果及特殊异常规则；这几项按 ISA 规范与独立样例检查，不能拿 SoftFloat 精确倒数、开方或普通整数转换当同语义 oracle。
- mask、vstart、NaN boxing、寄存器写回和 flags 累计是指令/模型行为：例如 vl=0、全屏蔽且初始 flags=0 时，BF16 标量 sNaN 不应让 NV 变成 1。用完整指令测试状态变化，不能把一个数值 helper 的 SoftFloat 对照当成覆盖。
- 有序归约核对规定顺序；无序归约检查规范允许的结果及异常。不同 DUT 使用不同合法归约树时，不能仅因末位与当前 Sail 顺序累加结果不同就判错。

### 本轮新增的具体错误样例

- `f32 1 + +inf` 错误置 NX，而交换两个输入不置 NX；异常算法只屏蔽了第一个输入的无穷情况。
- i32→f16、向正无穷舍入：`65505` 漏 OF；`-65520` 错置 OF 并漏 NX。
- ROD=6 的正常 RVV 窄化路径不能执行。
- BF16 向量乘加的标量源为 sNaN，但没有活动元素时，模型仍可能置 NV。

这些均为对当前源码的推导，尚未记录为 Isla 动态复现。原先的 Eq/qNaN、FMA 无效输入、Sub NX、FP→整数边界等问题没有因加入新清单而消失。

## 5. 不必立即改、但必须注明的限制

| 项目 | 结论 |
| --- | --- |
| FP/RM 从求解模型直接读回 | 抽样接口返回 None；直接读取会报不支持该类型。当前模型输出 BV/Bool 即可，内部 FP/RM 可以保留；以后若输出直接使用 FP/RM，才需补物化接口 |
| ToIEEE 文本打印 | 建议规范化；本机 Z3 4.16.0 接受现有形式，不能列为已确认解析失败 |
| 外部 SMT 条件解析器的 FP 语法 | 当前位串输入方案可不改；要允许用户直接写 FP 条件时再补语法 |
| 全局 linearize | 不作为浮点条件选择的解决方式：它会删除断言。逐个纯选择使用 ITE，保留架构分支 |
| ARM/x86 模型 | 用来检查原语是否通用；本次未实现或测试这两种 ISA，也不宣称支持 x87 ext80 等额外格式 |

## 6. 完整性与验证记录

- 通用 primop 注册表与逐项文档逐名对照，共 73 个；Sail 声明与当前 IR 按名称和有无函数体对照，共 79 个，分为 67+12。未把这些计数当成正确性证明。
- 另检查公开 ITE 及相关选择接口、专用实现全部操作分支、标量/RVV 主要调用和状态更新函数。Sail 支撑函数的范围及位置在独立清单中明确，不声称逐条指令都已经动态运行。
- 仅进行了独立命令行 Z3 4.16.0 的小表达式检查：FP 相等与普通相等、min 的正负零、ToIEEE 打印形式及简单混合公式。输入、命令和输出见 [primop 表第 7 节](inventory-primops.md)和[支撑层表第 3 节](inventory-support.md)。这些结果不能代替 Isla 实际链接的 Z3、生成 IR 或完整指令测试。
- 实施时先处理 I01–I05、I07，为 B 准备 I06 的 BF16 最小数值接口；B 通过最小 Sail/IR 编译冻结其接口形状，并打通一个完整比较样本及不同名、只返回 bits 的隔离加法演示。C/D 再完成共享异常、ROD、BF16 完整语义和全函数覆盖；D 在隔离候选确认替代并移除 I08 旧分发，E 将正式源码、IR 与严格配置同批切换并运行完整指令测试。精确异常算法的派发契约见 [接口与异常契约](exception-contract.md)，详细步骤见 [计划](plan.md)。
