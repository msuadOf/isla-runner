# M2 事实调查：区域内被调函数写全局状态（Codex 只读，2026-11-10）

代码基线 isla daf61c04（feat/isarch-path-cache）；IR 为旧全量实测的 rv64d.ir。文中路径约定见正文第三段。

结论：现有机制已经能合并寄存器最终值和全局 let，但同时实施“仅最外层区域入口栈深可写、寄存器至多写一次、读写分离”的限制；并非只缺少寄存器值的条件合并函数。相关注释明确保证的是前置状态和访问足迹，不保证精确的逐条读写序列。（`region_merge.rs:136`、`:171`、`:501`、`:719`）

给定 IR 中，`accrue_fflags` 的写状态调用链涉及 **`fcsr` 和 `mstatus`**。最后快照中，FVVTYPE 的 563 次、FWVFMATYPE 的 632 次 `callee_state_write` 均指向 `accrue_fflags` 的 `fcsr` 写入；FVFTYPE 最后快照没有该拒绝。快照不能证明后续没有其他写入。（`rv64d.ir:31525`、`:27889`、`:27925`；`FVVTYPE/isarch.log:1447`；`FWVFMATYPE/isarch.log:1441`；`FVFTYPE/isarch.log:1441`）

以下代码文件名约定：`region_merge.rs`、`region_summary.rs`、`frame.rs`、`task.rs`、`merge_*.rs`、`sample_*.rs` 均位于 `isla-lib/src/executor/`；`executor.rs`、`register.rs`、`primop_util.rs` 位于 `isla-lib/src/`。IR 指用户给定的 [rv64d.ir](旧全量实测工作树的 isla/rv64d.ir)；Sail 路径均相对给定的 `sail-riscv/model/`；日志路径均相对给定的 `runs/`。全程未修改或创建文件，未运行 cargo、isarch、make 或 git。

**1．推演访问日志与写许可**

- `AccessLog` 保存写集合、实际读取序列 `reads`、已经发布的读取 `published_reads`、每次读取的条件、当前臂条件，以及寄存器／局部变量／全局 let 的惰性初值；另有调用作用域和拒绝位置。局部初值以 `(call_scope, function, name)` 标识，全局 let 初值只以名字标识。（`region_merge.rs:30`；`executor.rs:110`）
- `entry_depth` 是**当前区域**开始时的 `backtrace.len()`，用于判断区域汇合、越界和栈逃逸；`write_depth` 在最外层设为入口栈深，嵌套区域继承父区域值；`depth` 则是区域嵌套层数，三者用途不同。（`region_merge.rs:183`、`:373`、`:498`）
- `writes_allowed` 初建日志时为 `true`；每步执行前更新为 `backtrace.len() == write_depth`。被调函数内再进入嵌套区域，也不会获得新的入口层写许可。（`region_merge.rs:171`、`:207`、`:501`、`:534`；`executor.rs:1971`）
- 返回调用者后，先恢复调用栈和函数，再恢复 `call_scope`、重新计算写许可，最后把返回值赋给调用者的目标。因此“辅助函数返回值写入调用者目标”和“辅助函数内部写全局”受不同栈深判断。（`executor.rs:2793`）
- 动态禁令仅对寄存器或 `state.lets` 中的名字检查 `writes_allowed`；被调函数写自身局部变量不触发 `CalleeStateWrite`。普通调用入栈／出栈只交换局部 `vars`，没有交换寄存器和全局 let。（`region_merge.rs:136`；`frame.rs:630`）
- 相关实现没有把“禁止被调函数写”单独解释成某一种快照或事务限制。明确注释是“调用不会重新授予入口层的写许可”；初值共享、读取发布顺序、写入偏序和回滚另有独立实现。（`region_merge.rs:47`、`:171`、`:568`、`:902`；`smt/transaction.rs:163`）

**2．寄存器读写纪律与回滚**

| 检查 | 代码实施的不变量 | 位置 |
|---|---|---|
| `RepeatedRegisterWrite` | 同一访问日志中，同一寄存器只能首次进入 `modified_regs` | `region_merge.rs:143` |
| `RegisterReadWrite` | 已进入 `read_regs` 的寄存器不能再写 | `region_merge.rs:147` |
| `RegisterReadAfterWrite` | 一旦已有任何寄存器写，之后不能再记录任何寄存器读，不限于同一个寄存器 | `region_merge.rs:49` |

- 这些检查使用共享访问日志；嵌套区域没有新建空日志，合并后还会合并读写集合。因此约束覆盖已有区域访问历史，不是仅检查当前一条调用。（`region_merge.rs:520`、`:951`）
- 臂内读取首先查局部变量，然后调用当前臂 `local_state.regs.get()`，再查全局 let。**读值不是从 `reads` 或 `published_reads` 中取出的**；后两者记录访问及控制事件是否重复发布。（`executor.rs:147`；`region_merge.rs:49`）
- 非 relaxed 寄存器读取最新写值；未初始化时创建符号值。relaxed 寄存器另有历史写入选择及读取缓存；两臂合并会拒绝基态中被访问的 relaxed 寄存器或带历史写入的寄存器。（`register.rs:134`、`:196`；`region_merge.rs:860`）
- 首个存活臂产生的惰性寄存器初值会提升到 `base`，第二臂从该基态克隆，复用同一个初值。局部变量和全局 let 也有对应提升逻辑。（`region_merge.rs:538`、`:568`）
- `record_read` 按 `(寄存器, accessor)` 的出现次数判断是否已发布；已发布的同序号读取只抑制再次发事件，并不替换当前读取值。注释要求读取事件先于使用该读取的 SMT 定义。（`region_merge.rs:47`）
- 写寄存器时先检查日志，再直接更新**当前臂的** `local_state.regs`；推演期间不立即发布 `WriteReg`。全局 let 直接更新当前臂 `lets`，该赋值分支不发布寄存器事件。（`executor.rs:802`）
- 字段写先用 `for_write=true` 取得原结构，替换字段后递归写回整个寄存器；这种为部分写取得原结构的操作不记录普通 `ReadReg`。（`executor.rs:164`、`:823`）
- 状态撤销依靠帧克隆与 `Arc::make_mut` 隔离：推演从 `base` 克隆臂，只有成功后才执行 `*frame = merged`。寄存器本身不由 solver 事务保存和恢复。（`region_merge.rs:517`、`:540`、`:734`；`frame.rs:59`）
- solver 事务另行撤销符号表、函数声明、模型、统计及事件缓冲；枚举 sort 定义作为 Context 全局状态保留。死臂先回滚，再加入该臂不可满足的约束；外层拒绝还会回滚已提交的内层结果。（`smt/transaction.rs:163`、`:188`、`:291`、`:294`；`region_merge.rs:426`）

**3．最终状态与事件怎样合并**

- `merge_states` 从 `base` 克隆结果，分别遍历两臂局部变量和全局 let。相同值直接保留；不同的已初始化值调用 `merge_val`；需要时给未初始化槽位补同一个符号初值。区域内新建、静态认定无需保留的局部槽位会删除。（`region_merge.rs:773`、`:800`）
- 写过的寄存器取两臂 `modified_regs` 的并集，读取两臂最终值；某臂尚无初始化值时，从合并基态取得初值。最终调用 `merge_val(condition, 左值, 右值)`，再写入结果帧。（`region_merge.rs:857`）
- 可表示且不同的布尔、位向量、枚举值会构造 ITE；结构体逐字段递归合并。相同值可直接保留。不同具体机器整数、字符串、引用、向量、列表等不会一概转为 ITE，而会拒绝。（`primop_util.rs:660`）
- `IncompatibleState` 的明确来源包括：需要保留的变量／let 两臂无法取得初始化值，以及 `merge_val` 返回一般不兼容错误。联合载荷错误单独映射为 `UnionPayload`；SMT 错误和超时保留原错误。（`region_merge.rs:839`、`:845`、`:876`）
- `RegisterSequence` 第一种来源：对两臂都读取的寄存器，过滤后得到的 `(寄存器, accessor)` **完整序列必须相同**，包括次数和顺序；这里只比较访问标识，不比较读值。（`region_merge.rs:886`）
- 第二种来源：把两臂写序列的相邻关系加入有向图；拓扑排序失败即拒绝。两臂写集合可以不同，顺序只要求能够同时保持两臂偏序，并非逐项一致。（`region_merge.rs:902`）
- 单臂寄存器读取允许存在，条件另存 `single_arm_reads`；共同读取条件按位置取 OR。主迹保留读取足迹，最外层成功后按合并写序补发整寄存器 `WriteReg`，值为合并最终值，accessor 为空；`_TLB` 不发布。（`region_merge.rs:719`、`:921`、`:934`）
- 事件没有做“两臂完整 trace 必须相等”的统一比较：两臂事务提交的事件进入缓冲，外层提交后发布；最后另加 `Fork`、`Merge` 标记。（`smt/transaction.rs:246`；`region_merge.rs:732`）
- 内存读采用并集语义；最外层记录保存主迹访存序号、完整条件和 `ReadMem`。普通内存写／其他写效应原语受 `StateEffect` 预检限制；设备 `Custom` 和 `Constrained` 区域的读取也会拒绝，因为 solver 无法回滚其外部效应。（`region_merge.rs:229`、`:387`；`region_summary.rs:253`；`primop/effects.rs:25`）

**4．静态效应摘要和预检**

- 效应等级按枚举顺序形成保守全序：`Pure < Unknown < ReadsState < ReadsMemory < WritesState < MayFork`，摘要通过 `max` 汇合；不是各效应独立的位集合。（`primop/effects.rs:18`、`:302`；`region_summary.rs:24`）
- `FunctionEffect` 分开保存效应、是否不返回及可选拒绝证据；效应达到 `WritesState` 不必然带拒绝证据，例如允许处理的约束原语。（`region_summary.rs:15`）
- `locals` 包括参数、`RETURN`、函数体所有 `Decl`／`Init` 名字。表达式读到集合外且非枚举成员的名字，提升为 `ReadsState`；目标根名字不在 `locals`、目标为 `Loc::Addr`，或调用向量寄存器写内建，则记 `WritesState + CalleeStateWrite`。（`region_summary.rs:128`、`:182`）
- 写局部字段按根名字判断；间接地址写即使根名字属于局部也仍列入拒绝条件。静态判断不依靠运行时 `state.regs`／`state.lets` 查找。（`region_summary.rs:185`）
- `CachedReject` 保存原因、原始函数、pc、源码位置；摘要沿调用图 SCC 逆拓扑传播，分量内迭代。它保存一个拒绝证据，不保存完整写集合或全部拒绝位置。（`region_summary.rs:24`、`:205`、`:263`）
- 区域开始前遍历 `region.nodes`，对调用使用被调摘要中的拒绝证据；缓存命中可直接拒绝。静态候选拒绝通常进入以 `(入口函数, 分支pc)` 为键的负缓存，保留被调函数的原始位置。（`region_merge.rs:321`、`:336`、`:355`；`region_summary.rs:234`）
- 真实执行循环每步仍做 `preflight`。已知不返回的调用作为异常出口在产生效应之前拒绝；未知外部实现的 `Unknown` 等级静态保留，实际到达才拒绝。（`executor.rs:1971`；`region_merge.rs:223`；`region_summary.rs:252`）

**5．`accrue_fflags` 的 IR、全局和回调**

- 直接调用链为 `zfp_add → zriscv_f16Add／zriscv_f32Add／zriscv_f64Add → zaccrue_fflags`：数值后端返回标志和结果，`fp_add` 将标志交给 `accrue_fflags` 后返回数值结果。（`rv64d.ir:64443`、`:64466`、`:64486`、`:64495`、`:64505`；`extensions/V/vext_fp_utils_insts.sail:181`）

| 全局 | 访问与条件 | 证据 |
|---|---|---|
| `fcsr` | 读取 FFLAGS、计算 OR、比较；只有标志改变才写回，之后再次读取供回调使用 | `rv64d.ir:31488`、`:31503`、`:31525`、`:31531`、`:31543` |
| `mstatus` | 经 `dirty_fd_context_if_present → dirty_fd_context` 读改写；FS `[14:13]` 置 Dirty=`11`，SD `[63]` 置 `1`，是两次整结构写回 | `rv64d.ir:27872`、`:27889`、`:27925`；`extensions/FD/fdext_regs.sail:110` |
| 全局 let `xlen` | `long_csr_write_callback` 读取，用于回调值截取及位宽判断；给定 IR 定义为 `64`，该链不写它 | `rv64d.ir:14478`、`:14497`、`:8854` |

- `dirty_fd_context_if_present` 检查 F 与 Zfinx 支持关系；给定 IR 中 `hartSupports(Ext_F)=true`、`hartSupports(Ext_Zfinx)=false`，这两个分支返回常量。因此标志改变后会进入 dirty 写入链。（`rv64d.ir:27936`、`:10978`、`:11136`）
- `accrue_fflags` 总会调用 `csr_name_write_callback("fflags", …)` 和 `("fcsr", …)`；dirty 链另调用 `long_csr_write_callback("mstatus", "mstatush", …)`。给定 RV64 IR 的 long 回调实际调用 `"mstatus"` 后返回，没有调用 `"mstatush"`。（`rv64d.ir:31540`、`:31551`、`:27930`、`:14472`）
- CSR 名字回调先做名字到编号映射，再调用 `csr_full_write_callback`；后者在给定 IR 中是局部元组赋值后返回 `()`，没有寄存器、内存或专门 CSR 事件操作。Sail 同样声明为 `pure` 并给出空函数体。（`rv64d.ir:14445`、`:14399`；`core/callbacks.sail:34`、`:60`）
- `configs/riscv64.toml` 还配置 `csr_full_write_callback="()"`；初始化配置值归 `Pure`，加载器可改写为 `PrimopReset`。这证明该配置的处理方式，不证明指定日志必然使用了此配置。（`configs/riscv64.toml:130`；`config.rs:1673`；`primop/effects.rs:332`；`ir.rs:1372`）
- 上述状态链没有 `ext_*` 扩展回调或 `print` 调用；`extStatus_to_bits` 是枚举编码函数，Dirty 映射为 `11`。链上断言通过 `$sail_assert` 执行。（`rv64d.ir:31485`、`:27865`、`:27936`、`:13157`、`:13027`）
- 执行器可按 `trace_functions` 配置为普通 IR 函数调用／返回增加 `Function` 事件；因此“CSR 回调函数体无专门事件”不等于开启函数跟踪后 trace 完全没有事件。（`executor.rs:2707`、`:2849`）
- 数值后端需与状态回调区分：Sail 把三个 `riscv_f*Add` 声明为 `pure`，给定 IR 仅有 `val` 声明。Rust 注册的通用 `fp_add` 是另一个浮点原语；加载器注释明确提到尚未实现的 RISC-V SoftFloat 原语，实际到达无实现调用会拒绝／报错。最后拒绝快照不能证明数值后端已执行成功。（`core/softfloat_interface.sail:38`、`:42`、`:46`；`rv64d.ir:23807`、`:23822`、`:23837`；`primop/float.rs:530`；`ir.rs:1386`；`executor.rs:1598`）

**7．已有条件合并、缓存、FastFacts 和 DAG**

- 已有 `merge_val`、`merge_val_nary` 和 `ite_phi`；前两者实施严格类型／形状兼容，后者递归按条件构造 ITE 链。另有 `merge_register_bindings_nary`，要求各输入寄存器均已初始化，并拒绝 relaxed／历史写入。（`primop_util.rs:556`、`:660`、`:737`、`:854`）

**8．现有测试构造与判据**
