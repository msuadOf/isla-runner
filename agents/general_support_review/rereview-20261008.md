## P1：拼接形成的合法访存地址被拒绝

`isla-lib/src/primop.rs:1602、1609` 将符号量与具体位串拼接的结果改为 `MixedBits`。`isla-lib/src/memory.rs:557、599` 的地址分派仍只接受 Bits／Symbolic，`primop/memory.rs` 的访存原语直接转交地址。

公开接口探针用 52 位符号页号与 12 位具体页内偏移拼成 64 位地址，再执行 8 字节读／写。基线 **2/2 通过**；当前 **0/2**，分别返回 `Non bitvector address in read` 和 `Non bitvector address in write`。这是正常拼接表达式新增的表示兼容回归，并非测试传入错误位宽。

Sail `model/sys/vmem.sail` 中存在同类物理地址拼接，但本轮没有证明某条实际 RISC-V 指令的 IR 必然保持这个表示直到访存原语；不能将公开接口复现扩大为整组 LOAD／STORE 验收结果。

建议复用既有 `replace_mixed_bits` 等规范化机制补齐访存边界，同时验证地址值、事件及访问约束，不撤销常量切片优化。证据：[测试源](rereview-evidence/memory-tests.rs)、[当前失败](rereview-evidence/head-memory-new.log)、[基线通过](rereview-evidence/base-memory-new.log)。

## P1：Monomorphize 对拼接结果静默失效

`isla-lib/src/executor.rs:2028` 只对 `Val::Symbolic` 执行枚举／具化。一个符号位与具体零拼接后再 `Monomorphize`，基线得到 **0、2 两个具体终态**；当前只得到 **一个终态**，源码核实它仍含符号片段。

这违反 Monomorphize 的具化契约，也绕过该处的分叉和采样记账。既有 85 项 executor 测试直接对 Symbolic 具化，因而没有覆盖 append 新表示。建议在该入口规范化后沿用原枚举流程，测试必须同时检查终态集合和结果具体性。

同一组探针另确认寄存器向量读／写索引接口收到拼接位串后也 Type；三个探针合计基线 **3/3**、当前 **0/3**。但当前 Sail 的 rX／rV／rF 索引签名为整数，两个索引探针只证明执行器接口接受域变化，不宣称实际指令已经触发。

证据：[三个测试](rereview-evidence/executor-tests.rs)、[当前失败](rereview-evidence/head-executor-new-final.log)、[基线通过](rereview-evidence/base-executor-new-final.log)。

## P1：选到不可编码模型后丢弃仍有合法见证的路径

`src/isarch/exec.rs:850–905` 先完成模型取值，再以具体前态运行编码 mapping；编码返回 None 时，`:942–963` 直接丢弃当前路径。当前 IR 的 VSETIVLI 编码要求 `currentlyEnabled(Ext_Zve32x)`，包括入口 `mstatus.VS != 0`；直接 execute 入口没有同样的前置检查。completion 可以选择 VS=0，因而后续编码拒绝。

同一 IR／配置／命令下，两种 VLEN 都复现：基线 VSETIVLI **12 gen**，当前 **0 gen**，四次 make 都退出 **0**。当前日志存在 12 个 Retire 完成终态、汇编打印成功，编码均 None。

仅在隔离快照增加诊断约束 `mstatus.VS != 0`，其余当前实现和 V128 IR 保持相同，即恢复 **12 gen**。移除该约束再运行，当前又为 0，基线仍为 12。因此不仅是旧样例减少：当前已存在可编码替代解，却因先选错一个模型而失去整条路径。

**使用同一具体前态编码的方向正确。** 旧版 mapping 使用执行后寄存器，旧 12 条见证的入口可译码性不能直接继承；恢复旧传参会重新引入状态不一致。应把编码／译码可行条件纳入见证求解，或在拒绝后继续寻找满足条件的模型。本轮诊断约束仅用于证明合法替代解，不是提交的修复方案。

外层 `SolveCollectorState::record_error` 仍只记录 Timeout／SMT。该政策基线已有，但本分支新增的不可编码 `Unreachable` 也被忽略，故 0 gen 仍退出 0；这使新拒绝无法成为可靠的验收失败信号。

证据：[四组完整对照](rereview-evidence/smoke-summary.json)、[当前 V128 日志](rereview-evidence/head-v128/log/VSETIVLI.log)、[基线 V128 JSON](rereview-evidence/base-v128/rv64_zVSETIVLI.json)、[诊断补丁](rereview-evidence/vsetivli-diagnostic.patch)、[诊断结果](rereview-evidence/vsetivli-diagnostic.json)、[恢复后复验](rereview-evidence/restored-smoke.json)。

## P2：断言转换破坏正常默认拒绝及压缩编码接续

`src/isarch/mod.rs:114–118` 只在 MatchFailure 后紧接固定函数尾部时承认正常 mapping 默认拒绝。`ir.rs::assertions_to_jumps` 会在函数尾追加断言处理块，`src/isarch_main.rs:500–505` 又对 solve-state 默认执行这个转换。

新增最小用例：普通编码函数执行一个真断言，然后正常默认拒绝；压缩编码函数可返回 `16'h0001`。基线通过并返回压缩编码；当前返回 `Err(MatchFailure)`，没有继续运行压缩编码器。断言并未失败，拒绝身份只是被尾部布局改变掩盖。

应保留默认拒绝的身份或根据可靠控制流识别，同时仍拒绝真正的内部／嵌套 MatchFailure。证据：[测试源](rereview-evidence/mapping-test.rs)、[当前失败](rereview-evidence/head-mapping-new.log)、[基线通过](rereview-evidence/base-mapping-new.log)。本轮没有宣称实际 RISC-V IR 某个 mapping 已触发这个人工 IR 组合。

## 语义和预期效果

| 改动 | 当前评价 |
| --- | --- |
| MixedBits 拼接／切片 | 位值等价、已知字段保持具体的优化有依据；算术和 FP 修复已通过，但执行器和访存接受域仍遗漏。非法固定切片改为 panic，空切片行为也有修正。 |
| 宽位格式化／模型物化 | 现有非零、高位、段序及 B64／B129 到 512 位的测试切题，本轮通过，未发现新反例。 |
| Model 具体值缓存 | 实例内缓存、completion 切换清空、Arbitrary／错误不缓存均有测试，本轮通过。 |
| 采样标记 | 随 frame 继承有直接测试，本轮通过；MixedBits 具化绕过的问题使整体契约仍不成立。 |
| mapping 严格校验 | 拒绝多结果和传播内部错误是有意变化，方向合理；与断言尾部转换的组合有回归。 |
| solve-state assert 两臂 | 实质改变控制流、分叉／签名／预算。并非纯重构；AssertionFailure 仍不会作为普通 gen 输出。 |
| 同模型指令／完整前后态 | 同一模型物化和宽前态有效；complete 指 Target 前态清单，RV64 不包含 PC／x0 等全部机器状态，未证明完整重放。编码可行性与选模仍不闭合。 |
| RV64 特权域／manifest | 有意收窄当前特权级、SXL／UXL／MPP 域，MPP reset 例外与现行模型一致；validated 只说明所列字段规则，不证明完整 mstatus 组合可达或硬件合法性。 |
| JSON | 新增 requested-instruction、完整前后态、state-domain，删除硬编码 arch.ext，属于输出 schema 变化。 |

因此不能称整组修改“语义不变”。部分是表示／性能优化，部分明确改变求解域、错误政策、断言行为和输出契约；它们的目标合理，但当前组合仍有缺陷。

缓存局部收益仍有证据：历史同一模型重复读取 20,000 次，Z3 调用 20,000→1；本轮缓存单测重新验证缓存命中不增加调用。这个缓存入口在三个修复提交中没有改变。没有新的端到端性能结论；完整状态物化、更多 SAT 检查和 assert 分叉也增加工作量。本轮 make 墙钟包含构建，且 VSETIVLI 工作结果不等价，不能当作提速对照。
